HTML로 MP4 만드는 HyperFrames, Windows에서 직접 시험해보니

2026-10-22 · 새AI실험노트 · 직접 확인 기록

한눈에 보기

  • HyperFrames는 HeyGen이 공개한 오픈소스(Apache-2.0) 영상 도구입니다. HTML·CSS와 시간 탐색이 되는 애니메이션(seekable animation)을 headless Chrome(화면 없이 돌아가는 크롬)과 FFmpeg로 MP4 파일로 만듭니다.
  • 2026-10-22에 Windows PC에서 v0.8.185를 시험했습니다. 프로젝트 생성과 정적 검사(lint)는 성공했고, MP4 렌더링(영상 파일로 뽑아내는 일)은 두 번 모두 실패했습니다. 확인 수준은 partial(일부 확인)입니다.
  • 로컬 렌더 엔진은 무료입니다. 다만 AI 코딩 에이전트, 클라우드, 음성·아바타 같은 선택 기능은 비용이 따로 들 수 있습니다.

오늘 쇼츠 첫 장면 (영상 캡처)

시작 전에 확인할 것

  • 어떤 도구인가: 일반 웹페이지를 넣으면 알아서 영상이 되는 도구가 아닙니다. 영상용 HTML을 직접 쓰거나 AI 에이전트로 만들게 한 뒤, 로컬 CLI(명령어로 쓰는 프로그램)로 렌더링하는 프레임워크입니다. AI 에이전트 연동은 선택 사항입니다. ([공식 저장소](https://github.com/heygen-com/hyperframes))
  • 필요한 것: Node.js 22 이상(자바스크립트 실행 프로그램), FFmpeg(영상 변환 프로그램), 실행 가능한 Chrome/Chromium이 필요합니다. 로컬 디스크와 CPU·RAM도 씁니다. 브라우저를 자동으로 설치하거나 외부 스크립트를 내려받을 때는 인터넷이 필요할 수 있습니다.
  • 요금·계정: 라이선스는 Apache-2.0입니다. 렌더링마다 내는 요금이나 상업용 사용 인원 제한은 없습니다. 로컬 렌더링은 HeyGen 크레딧을 쓰지 않습니다. 이번 시험(도움말·init·render)에서는 결제, 회원가입, API 키 입력, HeyGen 로그인이 모두 없었습니다. 코딩 에이전트 구독과 선택형 호스팅·음성·아바타·생성 미디어는 따로 돈이 들 수 있습니다. ([Quickstart](https://hyperframes.heygen.com/quickstart))
  • OS: CLI는 Windows에서 실행됩니다(우리 시험에서는 init까지 확인). 별도 데스크톱 앱인 [Studio](https://www.hyperframes.dev/studio)는 macOS·Linux용만 내려받을 수 있습니다. Windows와 Windows arm64는 Coming soon입니다. 이 앱은 브라우저로 여는 미리보기(preview)와 다른 것입니다.
  • 최근 업데이트:
  • [v0.8.160](https://github.com/heygen-com/hyperframes/releases/tag/v0.8.160)(2026-10-15): Windows에서 처음 렌더링할 때 새로 받은 브라우저·FFmpeg 파일에 접근할 수 있을 때까지 기다리도록 고쳤습니다.
  • [v0.8.185](https://github.com/heygen-com/hyperframes/releases/tag/v0.8.185)(2026-10-21, 한국 시간 Tags 화면에는 Oct 22로 표시): 캡처 모션 블러를 켜서 쓰는(opt-in) 기능으로 넣었습니다. cloud render --resolution 4k에서 투명 MOV·WebM도 쓸 수 있게 했습니다. 4K를 처음 지원한 업데이트는 아닙니다.
  • 관심도: 2026-10-22 [GitHub 주간 트렌딩](https://github.com/trending?since=weekly) 화면에서 누적 별 69,371개, 주간 증가 5,740개를 확인했습니다. npm 공식 API 기준 2026-10-12~10-18 다운로드는 510,551회입니다. 둘 다 바뀌는 숫자이고 사용자 수가 아닙니다.

설치 방법

아래 명령어는 PowerShell 같은 터미널(명령어를 글자로 입력하는 창)에 입력합니다.

1. 환경 점검 — 📄 공식 문서 기준

npx hyperframes doctor
  • 이게 보이면 성공: 공식 예시에는 'All checks passed'와 항목별 통과 표시가 나옵니다. 예시에 있는 버전 번호는 최소 요구 버전이 아닙니다.
  • 우리는 이 명령을 실행하지 않았습니다. ([CLI 문서](https://hyperframes.heygen.com/packages/cli#doctor))

2. 프로젝트 만들기 — 📄 공식 문서 기준 / ✅ 직접 해 봄(옵션 추가)

npx hyperframes init my-video
  • 이게 보이면 성공: 예제를 바탕으로 새 영상 프로젝트가 생깁니다. 문서상 기본 예제는 'centered Inter blank'입니다.
  • 우리가 실제로 입력한 형태는 아래와 같습니다.
$env:HYPERFRAMES_SKIP_SKILLS="1"; $env:DO_NOT_TRACK="1"; npx --yes hyperframes@0.8.185 init my-video --non-interactive
  • 결과: 0.83초가 걸렸고 파일 6개가 생겼습니다. 종료 코드는 exit 0이었습니다.
  • 막히면: --skip-skills 옵션은 지금 무시됩니다. 에이전트 스킬 설치를 건너뛰려면 HYPERFRAMES_SKIP_SKILLS=1 환경 변수를 써야 했습니다.

3. 프로젝트 폴더로 이동 — ✅ 직접 해 봄

cd my-video
  • 문서에는 따로 성공 문구가 설명되어 있지 않습니다.

4. (선택) Claude Code 플러그인 — 📄 공식 README 기준, 우리는 설치하지 않음

claude plugin marketplace add heygen-com/hyperframes
claude plugin install hyperframes@hyperframes
  • 설치하면 /hyperframes:hyperframes로 부릅니다. 계정 설정을 바꾸지 않는다는 규칙 때문에 이번에는 실행하지 않았습니다.

사용 방법

1. 영상 내용 쓰기 — ✅ 직접 해 봄

  • 우리 시험에서 index.html 기본값은 10초짜리 Title 자리표시자였습니다.
  • 우리는 제목을 "HTML → MP4"로 바꾸고, 길이를 5초로 줄이고, GSAP fade-up 애니메이션을 넣었습니다. 이건 사람이 아니라 Aside가 고친 HTML입니다. Claude 플러그인으로 만든 결과물이 아닙니다.
  • 원본을 백업할 때는 .html.bak 확장자로 저장하세요. 그래야 루트 컴포지션이 중복으로 잡히지 않습니다.

2. 미리보기 — 📄 공식 문서 기준

npx hyperframes preview
  • 이게 보이면 성공: HyperFrames Studio에서 영상 구성이 열립니다. 실행 결과에 Studio 프로젝트 URL과 서버 URL이 나옵니다.
  • 기본 포트는 3002입니다. 하지만 실제로 안내된 URL을 쓰세요.

3. 정적 검사 — ✅ 직접 해 봄

npx hyperframes lint
  • 이게 보이면 성공: 검사 결과가 나옵니다. Errors는 렌더링 전에 꼭 고쳐야 하고, Warnings는 문제가 될 수 있다는 뜻입니다.
  • 우리는 --json 옵션을 붙였습니다. 마지막에 ok true, 오류 0, 경고 0이 나왔습니다.

4. 브라우저 검사 — 📄 공식 문서 기준

npx hyperframes check
  • lint 오류가 있으면 브라우저 검사를 건너뜁니다. JSON 보고서에서 browserSkipped가 true면 layout·motion·contrast가 비어 있어도 통과가 아닙니다.

5. 렌더링 — 📄 공식 문서 기준 / ✅ 시도했지만 실패

npx hyperframes render
  • 우리가 실행한 명령은 npx --yes hyperframes@0.8.185 render --workers 1 --output renders/test.mp4입니다.
  • 성공 판단: 출력 파일이 실제로 있어야 합니다. 그리고 ffprobe로 길이·해상도·프레임 수를 확인해야 합니다. 우리는 이 단계까지 가지 못했습니다.

우리가 직접 해 본 결과

확인 수준: partial. 시험 환경은 Windows, Node.js v26.5.0, npm 11.17.0, hyperframes 0.8.185, workers 1입니다. 시험 전부터 FFmpeg와 Chrome이 설치되어 있었습니다.

| 소요 시간 | 한 일 | 결과 | |---|---|---| | 26.16초 | npx로 --help 첫 시도 | 실패: "지정된 경로를 찾을 수 없습니다", exit 3 | | 11.68초 | node.exe로 npx-cli.js 직접 실행해 --help | 성공: 다운로드 포함, v0.8.185 확인 | | 0.83초 | init my-video | 성공: 파일 6개 생성 | | 9.51초 | render 1차 | 실패: EPERM rename, MP4 없음 | | 62.68초 | 기존 Chrome을 지정하고 render 2차 | 실패: SIGKILL/ETIMEDOUT, MP4 없음 | | 0.28초 → 0.25초 | lint --json | 오류 1건 → 고친 뒤 통과 |

  • 위 시간은 명령 하나를 실행하는 데 걸린 시간입니다. 조사, 오류 해결, HTML 작성, 영상 제작까지 합친 전체 시간이 아닙니다. 초 단위로 잰 영상 제작 성공 기록은 없습니다.
  • lint를 통과한 뒤에는 렌더링을 다시 돌리지 않았습니다. lint 통과는 렌더링 성공의 증거가 아닙니다.
  • MP4가 만들어지지 않아서 ffprobe와 프레임 검사는 하지 못했습니다. Claude Code 플러그인도 시험하지 않았습니다.
  • 한계: Windows PC 한 대에서 각 단계를 몇 번씩만 시도한 결과입니다. 모든 Windows 환경에서 똑같다고 볼 수는 없습니다.

실제 init 출력 발췌와 측정값 11.68초·0.83초. 브라우저에 재표시한 로그임을 명시. 계정 플러그인 미설치 표시. (영상 캡처)

자주 막히는 곳

  • npx가 "지정된 경로를 찾을 수 없습니다"(exit 3)로 실패: 우리 PC에서는 Aside의 npx 래퍼가 격리 환경 변수와 충돌했습니다. 기존 node.exe로 npm의 npx-cli.js를 직접 실행하니 다운로드와 도움말이 됐습니다.
  • render 중 EPERM rename 오류: chrome-headless-shell 152.0.7977.30을 자동 설치하다가 났습니다. 보안 프로그램 때문인지, 권한이나 파일 잠금 때문인지는 확인하지 못했습니다.
  • 기존 Chrome을 지정해도 실패: 지금 셸에만 HYPERFRAMES_BROWSER_PATH를 지정할 수 있습니다. 우리 PC에서는 chrome.exe --version 응답이 시간 초과로 끝났습니다. 그래서 여기서 멈췄습니다. 보안 기능 해제, 관리자 실행, 재설치는 하지 않았습니다.
  • lint의 multiple_root_compositions: 백업 파일 index.original.html도 루트로 인식된 문제였습니다. .html.bak으로 이름을 바꾸니 해결됐습니다.
  • --skip-skills가 안 먹힘: HYPERFRAMES_SKIP_SKILLS=1 환경 변수를 쓰세요.
  • Windows용 Studio 앱이 없음: 아직 Coming soon입니다. CLI와 preview를 쓰세요.

실제 렌더링 오류 로그 발췌, 1차 EPERM·2차 ETIMEDOUT 및 MP4 미생성 결과. 경로 비식별·브라우저 재표시 명시. (영상 캡처)

정리

HyperFrames는 "HTML로 영상을 짠다"는 방식이 분명한 무료 로컬 렌더 엔진입니다. 우리 Windows PC에서는 설치와 프로젝트 생성까지 됐지만, 브라우저 준비 단계에서 막혀 MP4를 만들지 못했습니다. Windows에서 바로 영상이 나온다고 말할 수는 없는 결과입니다. 렌더링에 성공하면 그때 다시 기록하겠습니다. 시험 과정은 [쇼츠](https://youtube.com/shorts/X6cDlhHdSOY)에도 담았고, 원문 기록은 [AI 실험노트](https://compaction19-blip.github.io/ai-lab-notes/)에 모았습니다.
