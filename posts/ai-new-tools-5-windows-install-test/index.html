1. 제미나이 캔버스: PDF 한 장을 퀴즈 앱으로 (✅ 직접 해 봄, 10/19)

준비물: 구글 계정, 인터넷 브라우저. 설치·API 키는 필요 없어요.

1단계. 브라우저에서 gemini.google.com 에 들어가 구글 계정으로 로그인해요.

2단계. 입력창 왼쪽의 + 버튼 → 도구 더보기 → Canvas를 눌러요. 입력창에 'Canvas'라는 표시가 생기면 성공이에요.

3단계. 다시 + 버튼 → 파일 업로드로 PDF 1개를 올려요. 개인정보가 들어 있는 PDF는 올리지 마세요. 저희는 가상의 회사 보안 교육 자료를 직접 만들어 썼어요.

4단계. 이렇게 입력하고 보내요: 이 PDF로 퀴즈 앱 만들어줘. 문제 5개, 보기 선택 후 채점과 점수가 나오게.

캔버스 선택 + PDF 첨부 + 실제로 보낸 부탁(10/19 실제 화면)

5단계. 1~2분 기다려요. 저희는 약 90초 뒤(5초마다 확인, 1번 잰 값) 퀴즈 앱이 완성돼 있었어요.

6단계. '미리보기'에서 문제를 풀고 채점 버튼을 눌러요. 점수와 문항별 정답이 나오면 성공이에요. 저희는 5문제를 모두 맞혀 '총점 100점(합격)'이 나왔고, 틀린 문제에는 해설과 규정 근거가 함께 나왔어요.

채점 결과 '총점 100점(합격)'(10/19 실제 화면)

막히는 곳과 해결 (📄 공식 도움말 기준)

  • '파일이 포함된 채팅의 한도에 도달했습니다'가 뜨면: 일정 시간 업로드 한도예요. 시간이 지나 다시 해 보세요.
  • '업로드 용량이 너무 커서…'가 뜨면: 더 작은 파일로 나눠 올려 보세요.
  • 공유 링크가 휴대폰 제미나이 앱에서 안 열리면: 공유된 캔버스는 gemini.google.com 웹에서 열어야 해요.

비용: 공식 요금 표에는 무료 계정도 캔버스를 쓸 수 있다고 나와요(사용 한도는 요금제마다 달라요). 다만 저희는 구글 AI 프로 계정으로만 해 봤고, 무료 계정은 직접 확인하지 않았어요.

2. OpenScreen 2: 클릭한 곳을 자동으로 확대하는 무료 녹화기 (✅ 직접 해 봄, 10/20)

준비물: 윈도우 10(1903 이상) 또는 11. 무료(MIT 라이선스), 워터마크 없음.

1단계 (📄 공식 권장 방법). 터미널에 winget install --source msstore OpenScreen 을 입력하면 마이크로소프트 스토어 버전이 설치돼요. 또는 github.com/getopenscreen/openscreen 의 Releases에서 Openscreen.Setup.버전-x64.exe를 받아 실행해요. 서명이 없어서 파란 경고창이 뜨면 '추가 정보 → 실행'을 누르면 돼요.

참고로 저희는 시스템에 설치하지 않으려고, 공식 설치 파일(v2.1.2)에서 앱만 꺼내 시험 폴더에서 실행했어요. 내려받기 6.4초, 앱 꺼내기 9.1초가 걸렸어요.

2단계. 앱에서 녹화할 창이나 전체 화면을 고르고, 보여 주고 싶은 곳을 클릭하면서 녹화한 뒤 정지해요. 저희는 테스트 창을 10초 동안 녹화하며 버튼을 3번 눌렀어요.

3단계. 자동 줌(Automatic zooms)을 켜고 MP4로 내보내요. 자동 줌은 API 키 없이 돼요. 저희는 9.6초 만에 MP4가 나왔고, 약 4초 지점에서 클릭한 버튼 쪽으로 확대됐다가 끝에 전체 화면으로 돌아오면 성공이에요.

OpenScreen이 내보낸 MP4: 클릭한 버튼 쪽으로 자동 확대(10/20)

4단계 (선택). 클로드 코드에 연결하기: .exe 설치 버전이면 터미널에 claude mcp add openscreen -- "%LOCALAPPDATA%\Programs\Openscreen\Openscreen.exe" mcp 를 입력해요. claude mcp list에서 Connected가 보이면 연결 성공이에요. 저희는 등록 0.8초, 연결 확인 1.9초였어요. 스토어 버전은 앱의 AI settings → MCP server를 켜고 화면에 나온 명령을 쓰는 게 공식 안내예요.

막히는 곳과 해결 (✅ 저희가 실제로 겪은 것)

  • 데모 스킬 설치 npx skills add getopenscreen/openscreen --skill openscreen-demo가 'spawn git ENOENT'로 실패했어요. 이 PC에 깃(Git)이 없어서예요. 깃과 노드가 깔린 PC에서 다시 해야 해요.
  • 저희가 해 보지 않은 것: 목소리를 자막으로 바꾸기(처음에 약 264MB 모델 다운로드 필요), 앱 안 AI 편집(본인 API 키 필요), 클로드 코드로 실제 편집 시키기.

3. earshot: AI가 소리를 듣고 판별하는 도구 (✅ 직접 해 봄, 10/21 · 조건부)

준비물: 파이썬 3.10 이상, ffmpeg. 무료(MIT), GPU 없이 CPU로 돌아가고 핵심 기능은 API 키가 필요 없어요(공식 문서).

1단계. 터미널에서 python --version 과 ffprobe -version 을 입력해 둘 다 버전 숫자가 나오는지 확인해요. 안 나오면 먼저 설치해야 해요.

2단계. github.com/Leonxlnx/earshot 에서 Code → Download ZIP으로 받아 시험 폴더에 풀어요. 깃이 있으면 git clone https://github.com/Leonxlnx/earshot 도 돼요. 저희는 깃이 없어서 ZIP을 썼어요.

3단계. 풀린 폴더에서 가상 환경을 만들어요: python -m venv .venv

4단계. CPU용 파이토치를 먼저 설치해요: .\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu (저희는 154초)

5단계. earshot을 설치해요: .\.venv\Scripts\python.exe -m pip install -e . (저희는 MCP 기능까지 넣은 .[mcp]로 260초. 4단계와 합쳐 약 7분)

6단계. 진단을 돌려요: .\.venv\Scripts\python.exe -m earshot doctor --load 처음에는 소리 모델 약 1.1GB를 내려받으니 시간이 걸려요.

7단계. 소리 파일로 시험해요: .\.venv\Scripts\python.exe -m earshot describe .\sample-doorbell.ogg 저희는 3.7초짜리 초인종 효과음(CC0, 위키미디어 공용)을 넣었더니 51.49초 만에 결과에 'a doorbell'(초인종)이 나왔어요. 이게 보이면 성공이에요.

earshot 실제 판별 로그 발췌: 51.49초 만에 'a doorbell'(10/21, 로그를 큰 글씨로 다시 표시)

주의할 점

  • 저희가 시험한 소리는 딱 1개라서, 정확도 몇 %라고 말할 수 없어요.
  • 공식 문서에도 취향·감정·말의 내용은 판단하지 못한다고 나와 있어요.
  • 실제 공식 안내에는 임시 폴더·캐시 위치를 시험 폴더로 지정하는 방법도 있으니, PC를 깨끗하게 유지하고 싶다면 공식 README의 설치 부분을 함께 보세요.

4. diagram-design: 말로 설명하면 보고서 도표를 그려 주는 스킬 (✅ 직접 해 봄, 10/23 · 조건부)

준비물: 클로드(웹 또는 클로드 코드) 계정. 스킬 자체는 무료(MIT)지만, AI 사용료는 쓰는 서비스 요금제를 따라요. 공식 README는 45종 도표를 지원한다고 하지만 저희는 순서도 1종만 해 봤어요.

저희가 해 본 세 번의 시도

  • 1·2번째: 클로드 코드에 스킬 폴더를 넣고 '가상 쇼핑몰 주문 흐름 순서도'를 부탁 → 저희가 걸어 둔 안전 제한 때문에 파일 쓰기가 막혀 결과 파일 0개(159초, 145초). 명령은 정상 종료였지만 파일이 없으니 실패로 봤어요.
  • 3번째: 클로드 웹에 공식 설명서(SKILL.md)와 참고 문서를 직접 붙여 넣고 같은 부탁 → 약 177초 뒤 순서도 완성. HTML로 내려받으니 외부 주소가 하나도 없는 파일 1개(10,854바이트)였어요.

따라 하기 (저희가 성공한 방법)

1단계. github.com/cathrynlavery/diagram-design 에서 Code → Download ZIP으로 받아 풀어요.

2단계. skills/diagram-design 폴더 안의 SKILL.md와 references 폴더의 관련 문서(스타일 가이드, 순서도 설명 등)를 열어 둬요.

3단계. claude.ai 새 대화에 그 내용을 붙여 넣고 이렇게 부탁해요: 이 스킬로 가상 쇼핑몰 주문→결제→배송→수령→반품/환불 흐름을 순서도로 그려줘. 한글은 시스템 폰트, 외부 요청 없는 HTML+inline SVG 한 파일로.

4단계. 결과(아티팩트)가 나오면 메뉴에서 내보내기 → HTML로 저장해요. 브라우저에서 순서도가 보이면 성공이에요.

클로드 웹으로 만든 순서도 HTML을 연 화면(10/23, 가상 데이터)

📄 공식 문서 기준(저희는 안 해 봄): 클로드 코드·커서 같은 도구에서는 npx skills add cathrynlavery/diagram-design 로 설치하는 게 정식 방법이에요. 이때 파일 쓰기 권한을 허락해야 결과 파일이 저장돼요.

5. HyperFrames: HTML을 MP4 영상으로 (✅ 직접 해 봄, 10/22 · 이번 PC에서 실패)

준비물: 노드 22 이상, FFmpeg, 실행되는 크롬. 무료 오픈소스(Apache-2.0).

저희가 한 순서

1단계. 터미널에서 npx --yes hyperframes@0.8.185 init my-video --non-interactive (📄 공식 명령. 저희 PC는 npx 실행기가 경로 오류를 내서 같은 명령을 node로 직접 실행했어요) → 새 프로젝트 폴더 생성 성공(프로그램 받기·도움말 11.68초, 새 프로젝트 0.83초).

2단계. my-video 폴더의 index.html에 제목과 애니메이션을 작성.

3단계. npx --yes hyperframes@0.8.185 render --output renders/test.mp4 → 여기서 실패했어요.

HyperFrames 렌더링 실패 로그 발췌: EPERM·ETIMEDOUT, MP4 0개(10/22)

막히는 곳 (✅ 저희가 실제로 겪은 것)

  • 1차: 렌더링용 크롬을 자동으로 설치하다가 'EPERM(권한 없음)' 오류로 멈췄어요.
  • 2차: 원래 깔린 크롬을 HYPERFRAMES_BROWSER_PATH로 지정했더니, 크롬이 응답하지 않아 시간 초과로 끝났어요.
  • 결과: MP4 파일 0개. 원인이 보안 프로그램인지 권한 문제인지는 확정하지 못했고, 보안 설정은 일부러 끄지 않았어요. 보안 기능을 끄면서까지 시도하지는 마세요.
  • 정적 검사(lint)를 통과해도 영상이 만들어진 건 아니에요. renders 폴더에 MP4가 실제로 생기고 재생돼야 성공이에요.
  • 📄 공식 안내 기준으로 윈도우용 네이티브 스튜디오 앱은 아직 'Coming soon'이에요.

새 AI 도구를 처음 깔 때 순서

1. 설치가 필요 없는 웹 도구부터 써 보기.

2. 깃·노드·파이썬 같은 준비물이 필요한지 공식 README에서 먼저 확인하기.
