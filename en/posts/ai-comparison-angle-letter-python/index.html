Introduction

When transferring numbers from an AI response into a report or code, even small discrepancies need checking. A short, clear answer can make it tempting to skip review. But a number given without explanation does not tell you whether the model read the question's conditions correctly. Office workers and developers need not just quick answers, but also a way to verify them.

In the experiment on October 21, 2026, GPT and Claude answered all three questions correctly. Gemini miscounted the lowercase e characters, answering two questions correctly. Each model received the same questions once, with no retries. In an additional set intended to break the tie for first place, all three models answered correctly. GPT and Claude therefore remained tied for first, with no sole winner.

Experiment Design

The questions covered solving an equation involving vertically opposite angles, counting lowercase e characters, and predicting Python's sorting output. Together, they test not just calculation, but also whether a model identifies what it must answer and which comparison rule to apply.

The first question gave two equal angles as (3y-24)° and (y+6)°. It asked for y, not the angle measure. The second question asked the models to count only the lowercase e characters in nevertheless excellence. The third requested the single line of output from print(sorted([10, 9, 100], key=str)). All questions instructed the models to omit explanations.

The reference answers, in order, were 15, 8, and [10, 100, 9]. Establishing the correct answers in advance prevents plausible-looking responses from shifting the scoring criteria. This makes it possible to check whether the requested values and actual output match, rather than judging the length or tone of an explanation.

The models used were GPT-6.1 Sol High in Work mode, Claude Opus 5.5 at Medium (중간) in an Incognito (시크릿) session, and Gemini 4 Argon in Temporary Chat (임시 채팅). Because GPT and Claude tied on the first set, each model received one additional attempt at a harder second set, fixed in advance, in a new conversation. This was distinct from a retry asking a model to revise its answers to the same questions.

Why These Results Occurred

The catch in the first question is identifying which quantity the calculated value represents. Vertically opposite angles are equal, so we set 3y-24=y+6. Subtracting y from both sides and adding 24 gives 2y=30, so y is 15. Substituting this into the original expressions gives an angle of 21 degrees. Although 21 degrees is a valid value that appears in the calculation, it is not the answer requested here. All three models respected this distinction.

The second question highlights the difference between recognizing familiar words and counting their characters one by one. nevertheless contains 4 e characters, and excellence also contains 4. The total is 8. Breaking the count down by word makes it easier to see where Gemini's answer of 7 differs from the correct answer.

In its explanation afterward, Gemini stated that it had missed one e while processing the words as tokens and estimating the count. However, this is the model's own explanation. This record alone cannot establish what computation actually took place internally. The observed facts are that its initial answer was 7 and the correct answer is 8.

In the third question, key=str changes the comparison rule. Instead of comparing the elements by numerical value, it sorts them using the strings "10", "9", and "100". "10" matches the beginning of "100" and is shorter, so it comes first. "9" comes after "1" based on the first character. The result is therefore [10, 100, 9]. Only the sorting key uses strings; the elements in the resulting list remain the original numbers.

Conclusion

The outcome of this comparison was a tie between GPT and Claude for first place, with no sole winner. In practical work, it is worth establishing a procedure for checking answers as well as choosing which model to use.

  • Before calculating, write down whether the requested value is a variable or an angle.
  • Count characters word by word, then check the total.
  • In code, first identify conditions such as key that change the result.
  • Compare predicted output against the result of actually running the code.
  • Record explanations of errors separately from the initial answers.

Each set involved one attempt per model, and the first set was limited to 3 questions. Even getting every answer right across both sets does not establish performance on other tasks or repeated runs.
