Introduction

What should you check before copying AI-generated numbers into a report or code? It is easy to focus only on the calculation, but first you need to check whether the answer actually addresses the question in front of you. If the questions and answers do not match, even an answer key cannot make the scoring reliable.

The conclusion recorded on 2026-10-23 is 3 points for GPT and Gemini, and 2 points for Claude. The conditions were 1 attempt at the same questions, with 0 retries. However, the attached questions and answer key do not match the actual responses. These scores should therefore be presented as the results listed in the record, not as verified scores for the three attached questions.

The key is to distinguish the claim that Claude counted one too many from the evidence supporting it. Looking at the original responses helps separate what can be verified from what remains unverified.

Experiment Design

There are three attached questions. The first asks for the time needed to climb stairs, including rest breaks. The second asks how many three-digit numbers satisfy several conditions. The third asks for the output of Python code that removes elements while iterating over a list.

The answer key, in order, is 79, 12, and [4, 2, 5]. An answer key provides a consistent basis for comparison, without being swayed by an AI's tone or the length of its explanation. However, the record does not specify when the answers were finalized or give a separate reason for choosing these questions.

The verifiable procedure was to give each of the three AIs the same questions once, with no retries. The models are listed as GPT-6.1 Sol High, Gemini 4 Argon, and Claude Opus 5.5 Medium.

This raises an issue that needs to be resolved first. The results description says “2nd set,” but the number of sets attempted is recorded as 1. We need to establish which set of questions belongs with which answers.

Why Did These Results Occur?

We can explain the pitfalls in the attached questions themselves. However, these solutions do not explain the difference between the saved answers of 1489 and 1490.

In the stair problem, you need to count the intervals between floors rather than the floors themselves. From floor 1 to floor 4, there are three intervals, and floor 2 is the only intermediate even-numbered floor where you rest. Subtracting the 3-second break from 33 seconds leaves 30 seconds of movement. Each interval takes 10 seconds.

From floor 1 to floor 8, there are seven intervals, so movement takes 70 seconds. The breaks on floors 2, 4, and 6 total 9 seconds. There is no break at the destination, floor 8, so the total is 79 seconds.

The three-digit number problem requires applying all the conditions together. The number must be even, its digits must sum to 8, and all three digits must be different. The numbers that satisfy these conditions are 134, 152, 170, 206, 260, 314, 350, 512, 530, 602, 620, and 710: 12 in total. Counting only by the digit sum can lead you to overlook the distinct-digit condition.

In the Python problem, removing an element shifts the later elements forward. Since iteration continues to the next position, some elements are skipped. This code removes 2, 4, and 2 in sequence, leaving [4, 2, 5].

Meanwhile, Claude's follow-up explanation suggests that it may have counted one extra case while manually dividing up and counting seven-digit numbers subject to divisibility conditions. That is a different problem from the attached three-digit number question. Claude also stated that it could not identify the exact incorrect case without checking the calculation. This should not be rewritten as an established cause of the error.

Conclusion

The difference confirmed in these materials is between the saved answers of 1489 and 1490. The recorded scores are 3 points each for GPT and Gemini, and 2 points for Claude, but the comparison remains incomplete until the question set associated with those scores is identified.

For practical work, check the following.

  • Give the questions, responses, and answer key the same set name.
  • Record movement time and rest time separately in time calculations.
  • For counting problems, compare the cases excluded by each condition against the complete list.
  • Verify code output by running the code.
  • Distinguish follow-up explanations from directly verified causes of errors.

The recorded conditions were 1 attempt and 3 questions. This small sample is not enough to judge the models' overall calculation abilities, and the correspondence between the questions and answers still needs verification.

Original Experiment Prompt and Actual Responses
