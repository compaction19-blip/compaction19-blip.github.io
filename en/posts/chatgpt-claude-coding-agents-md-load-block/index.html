What to Check Before You Start

When you launch an AI coding agent—an AI program that reads and edits code for you—in a folder created by someone else, such as an external repository or a downloads folder, that folder's AGENTS.md file, which contains instructions for AI, may be added to the conversation automatically. Security articles discussing this issue have been circulating, but we did not review those original articles or reproduce the attacks for this test.

Claude Code (Installation guide, Pricing)

  • Required account: A Pro, Max, Team, Enterprise, or Console account. The free claude.ai plan does not include Claude Code. Signing in through a subscription and using separately billed API access are different options.
  • Pricing (official): Pro costs $20 per month with monthly billing, or $200 paid annually (about $17 per month). Max starts at $100 per month. Regional pricing, taxes, and organizational contract terms apply separately.
  • Operating systems and requirements: Windows 10 1809+/Server 2019+, macOS 13+, Ubuntu 20.04+, Debian 10+, Alpine 3.19+, at least 4GB RAM, and an internet connection. The npm distribution requires Node.js 22+.
  • Version (the program's release number): Direct AGENTS.md support starts with v2.1.277 (released 2026-09-18). /memory listing starts with v2.1.280, and v2.1.281 or later is recommended to avoid compatibility limitations.

Codex CLI (Authentication, Pricing)

  • Sign in with a ChatGPT subscription or use an API key. Plus, which includes the CLI, costs $20 per month, and Pro starts at $100 per month. Business/Enterprise/Edu follow organizational terms, while API key usage is billed separately based on consumption.
  • Do not interpret limited desktop availability on the Free/Go plans as "the CLI is free too."

How to Use It

1. Use AGENTS.md alone ✅ Tested hands-on ① Create AGENTS.md in the folder, add the line below, and ask Reply READY in a new Claude session.

   For this test only, include the literal marker [AGENTS-OK] in your reply.

② If you see READY [AGENTS-OK], automatic loading worked. ③ If the marker does not appear, check the CLAUDE files in parent folders and your version. 2. Add CLAUDE.md ✅ Tested hands-on ① Add a CLAUDE.md file in the same folder with an instruction to output the [CLAUDE-OK] marker. ② In the default mode, only READY [CLAUDE-OK] appears. ③ If you have changed your account settings before, do not assume they are currently at their defaults. 3. Load both files ✅ Tested hands-on ① Create a test JSON file outside the working folder, then launch Claude with that file specified.

   {"pluginConfigs":{"cc-plugin-agents-md@builtin":{"options":{"instructionFiles":"claude-md-and-agents-md"}}}}
   claude --settings <test JSON path>

② If READY [CLAUDE-OK] [AGENTS-OK] appears, it worked. ③ This JSON is ignored if you use it as a project settings file such as .claude/settings.json. In versions earlier than v2.1.285, the plugin (an add-on component) ID is agents-md@builtin. 4. Disable AGENTS.md ✅ Tested hands-on ① In the same JSON file, change the instructionFiles value to claude-md and launch a new session. ② A folder containing both files returns only READY [CLAUDE-OK], while a folder containing only AGENTS.md returns only READY. ③ Launching again without this option restores the original settings. We did not touch ~/.claude/settings.json. 5. Change it in the interactive interface 📄 Based on official documentation: You can change it through /config → Project instructions and view the loaded files with /memory. We did not click through this ourselves. 6. Codex rules 📄 Based on official documentation (AGENTS.md documentation)

  • At startup, Codex combines instructions from the global CODEX_HOME with instructions from the project root (usually the Git root) down to the current folder. If it cannot find a root, it checks only the current folder.
  • It selects at most one file per folder, in the order AGENTS.override.md → AGENTS.md → fallback. The default limit is 32 KiB.
  • An override file replaces AGENTS.md in the same folder; it does not block all subfolders. We do not recommend an empty override file as a reliable blocking method.
  • project_doc_max_bytes = 0 is the byte-limit setting described in the configuration documentation. We could not verify its blocking effect in this test.

Common Sticking Points

  • AGENTS.md is not being read: If CLAUDE.md, .claude/CLAUDE.md, or CLAUDE.local.md exists in the current folder or a parent folder, the default mode uses that file first. However, ~/.claude/CLAUDE.md, managed CLAUDE.md, and .claude/rules are not included in this check. AGENTS.md may also go unread if the plugin is disabled or in the first session immediately after certain upgrades.
  • It does not appear in /memory: Versions earlier than v2.1.280 do not show it in the list. In that case, check whether the marker appears in the response.
  • No markers appear at all: Check whether --setting-sources is empty. We encountered this ourselves.
  • Codex 401 error: This occurs when the isolated CODEX_HOME has no login credentials. You need an authorized, isolated login environment.
  • "claude-md mode means it is safe" is incorrect: Instruction files are conversation context, not enforced security policies. If CLAUDE.md contains an import of @AGENTS.md, that file may be included.

Checklist when asking AI similar questions 1. Before running anything, manually check the instruction files in the current folder and its parent folders. 2. Read the contents of instruction files in external repositories before running anything. 3. Use a harmless marker (for example, [AGENTS-OK]) to verify that the instructions actually take effect. 4. Check the version with claude --version and confirm that the feature is supported.

Summary

In the default mode, Claude Code read AGENTS.md only when no CLAUDE files were present, and it stopped reading AGENTS.md when switched to claude-md mode. According to the official documentation, Codex looks for AGENTS.md by default, but the outcome depends on the root, working path, overrides, and size limit. We could not verify that hands-on this time. Next time, we will test Codex again with the same markers in an authorized login environment.
