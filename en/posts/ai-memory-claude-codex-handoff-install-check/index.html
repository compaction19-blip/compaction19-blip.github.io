At a Glance

  • ai-memory is free, open-source software (MIT) that lets more than 20 AI coding tools, including Claude Code and Codex, share a single memory. Its goal is to reduce the need to explain your work again whenever you switch tools.
  • We downloaded the official ZIP file on Windows. We verified that the checksum matched (a checksum is like a fingerprint used to check whether a file is genuine), and we saw firsthand that it printed the version ai-memory 3.2.2.
  • However, we did not run the core feature: "having Codex pick up work started in Claude Code." Our verification level this time is partial (only some aspects checked).

Before You Start

  • Cost: ai-memory itself is free software under the MIT license. The official website has no sign-up process. According to the official description, basic capture, search, and handoff work without LLM calls or a model API key (a value that works like a password for accessing a paid AI service). However, optional features such as LLM integration, embeddings, and memory rewriting may use separately configured providers, so we cannot call everything free.
  • Accounts: Coding agents such as Claude Code and Codex (AI tools that write code for you) may each require an account or access permissions. We did not check agent subscription plans or login status this time.
  • Operating systems: Officially supported environments are Linux, macOS, and Windows WSL2 (a Linux environment running inside Windows). Native Windows is labeled Experimental. A Windows x86_64 ZIP distribution is available.
  • Privacy: Do not use real company code, personal information, or existing conversation histories. Official warnings say that the first session may import recent local agent history, credential filters may miss sensitive text, and records may be incomplete or outdated.
  • Version labels: At the time of our check, v3.2.2 was marked Latest on the GitHub release page. However, the banner on the official Korean-language website still showed v3.2.1.

Installation Methods

Enter commands in a terminal (a black window where you give the computer text instructions). On Windows, PowerShell serves that role. Choose only one of methods 1 and 2 below, whichever suits your environment.

1. Windows method (📄 Based on official documentation; we did not run it)

$env:AI_MEMORY_VERSION='3.2.2'; irm https://github.com/akitaonrails/ai-memory/releases/download/v3.2.2/install.ps1 | iex
  • What success looks like: According to the official Windows documentation, ai-memory.exe is installed in %LOCALAPPDATA%\Programs\ai-memory, and that folder is added to the user PATH (the list of locations that lets you run commands from anywhere). The documentation does not specify a fixed completion message.
  • If you get stuck: The installer refuses to install if the checksum does not match.

2. Linux, macOS, and WSL2 method (📄 Based on official documentation; we did not run it)

curl -fsSL https://github.com/akitaonrails/ai-memory/releases/download/v3.2.2/install.sh | AI_MEMORY_VERSION=3.2.2 sh
  • What success looks like: Files are extracted to ~/.local/lib/ai-memory, and ~/.local/bin/ai-memory becomes a link pointing to the executable.
  • If you get stuck: If SHA-256 verification fails, the process stops before extraction.

3. ZIP method for verification without system changes (✅ Tested firsthand)

We tested only in a newly created empty folder, without adding anything to PATH or using administrator privileges.

Invoke-WebRequest -Uri https://github.com/akitaonrails/ai-memory/releases/latest/download/ai-memory-windows-x86_64.zip -OutFile .\ai-memory-windows-x86_64.zip
Get-FileHash .\ai-memory-windows-x86_64.zip -Algorithm SHA256
Expand-Archive .\ai-memory-windows-x86_64.zip -DestinationPath .\ai-memory-v3.2.2
.\ai-memory-v3.2.2\ai-memory.exe --version
  • What success looks like: The Get-FileHash result matches the SHA-256 published on the release page, and running --version prints ai-memory 3.2.2.
  • If you get stuck: Do not run it if the hash differs. Also, the latest address downloads whichever version is latest at the time. When we downloaded it, the latest version was v3.2.2.

How to Use It

All of these steps are 📄 based on official documentation; we did not run them.

1. Enter ai-memory setup --plan. It only shows a plan of what would change, then exits. Detected agents are listed with numbers and the evidence used to identify them. It does not change files or settings. 2. Enter ai-memory setup. This creates the data folder, registers the server to start automatically at logon, and connects agents through MCP (a standard for connecting AI tools to external capabilities), hooks (actions that run automatically at specific points), and skills. A change plan and confirmation prompt appear, but seeing the prompt does not mean setup is complete. 3. Start Claude Code with ai-memory run claude, do some work, and then exit. Before this step, Claude Code and Codex CLI must each be installed and logged in (we did not check that state this time). 4. Run ai-memory run codex in the same folder. The official README describes this handoff workflow. Our verification log does not include a success screen for this step.

Note: ai-memory init only initializes the data folder. init alone does not complete the server, hook, and MCP integrations.

Our Firsthand Results

Our verdict is partial. Here is what we did, in order.

  • Why we chose it: v3.2.0, v3.2.1, and v3.2.2 were released in quick succession over about 23 hours on October 22–23 (Korea time). We were also curious about its claim to reduce the hassle of explaining "what I was just working on" when switching between Claude Code and Codex.
  • Source review: We opened the GitHub repository, official website, release list, and Windows documentation directly in a browser.
  • Download: 2.378 seconds.
  • Checksum check: 0.043 seconds. It matched the published SHA-256 84814a55…169b. We also checked all 203 entries in the ZIP for unsafe paths, and all passed.
  • Extraction: 2.440 seconds. The measured intervals up to this point totaled 4.861 seconds. This excludes manual work and time spent reading documentation.
  • Execution: --version 0.899 seconds (exit code 0, ai-memory 3.2.2), --help 0.049 seconds, run --help 0.045 seconds, setup --help 0.054 seconds. All four exited normally.
  • Cleanup: We confirmed that 0 test processes remained. We did not change PATH, services, or existing agent settings.

What differed from our expectations: Our initial plan was to perform the initial setup with ai-memory init. However, the official quick setup used ai-memory setup. The star count shown on the GitHub button (13.1k) also differed from the count on the official website (12,714).

Where we stopped: install.ps1 and setup can change PATH, the server's logon startup configuration, and agent settings, so we did not run them during this unattended verification. As a result, we could not test an actual handoff, score how many of the 3 key points matched, or measure the time from installation to handoff.

The limitations are clear: this was 1 attempt, limited to installation checks.

Common Sticking Points

  • If the hash differs: Do not run it. The official installer also refuses to install.
  • If it is unstable on Windows: Native Windows is Experimental. WSL2 is the officially supported Windows environment.
  • If you ran only init and integrations do not work: setup handles the integrations.
  • If you are worried about what will change: Read the plan first with ai-memory setup --plan.
  • If the version numbers differ: Use the Latest label on the GitHub release page as your reference.

Checklist for testing the handoff yourself

1. Test only in a dummy example project folder. 2. Without giving any explanation, ask the second tool to describe what the first tool did and what remains to be done, then compare its answer with the 3 key points you wrote down. 3. Double-check important details rather than relying on memory alone (the official documentation also warns that records may be incomplete).
