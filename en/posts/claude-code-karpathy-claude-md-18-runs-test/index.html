How to Add Karpathy Rules (CLAUDE.md) to Claude Code, Tested in 18 Runs: It Asked First on Ambiguous Requests

2026-10-28 · SaeAI Lab Notes (새AI실험노트) · Hands-on testing (the same 3 tasks × 3 runs × 2 conditions = 18 runs)

Actual execution screen for feature addition B (Karpathy rules), run 3: cart.py +10 lines, hidden tests 3/3

Test environment and limitations · Hands-on testing (the same 3 tasks × 3 runs × 2 conditions = 18 runs) · These results are actual records from 3 runs per condition on a single Windows PC. Results may differ with other code, models, or versions.

We tested 'Andrej Karpathy Skills' (a single CLAUDE.md file), often recommended on YouTube as "the first thing beginners should install," before and after adding it to Claude Code. We ran the same 3 tasks 3 times under each condition, for 18 runs in total. The short verdict: helpful under certain conditions. It made a big difference with ambiguous requests (asking first went from 0/3 → 2/3), slightly reduced the code for a feature addition (14 lines → 10 lines), and made no difference when fixing a clearly defined bug.

This guide covers ① the setup steps, ② the exact prompts we sent, and ③ all 18 results, so even first-time users can follow along.

Results at a Glance

  • Ambiguous request ('Make the receipt look a bit nicer'): Large effect — asked first A 0/3 → B 2/3, average lines changed 33.7 lines → 4.3 lines
  • Feature addition (a function to change quantities): Small effect — lines changed 14·14·14 → 10·10·10, unrequested behavior added 3 times → 0 times
  • Bug fix (10% coupon): No difference — the same one-line fix in all 6 runs, with all tests passed

What Are Karpathy Skills?

  • Source video: Nomad Coders, 「How to Get Rid of Garbage Code ☠️」 (published 2026-10-04, with 149,985 views as of 10/28). The file was introduced in the chapter labeled 03:05 「(2) Karpathy Skills」 in the description. https://www.youtube.com/watch?v=3JCgiVYlLFo
  • Repository: https://github.com/multica-ai/andrej-karpathy-skills (225,469 stars as of 10/28). Karpathy did not create it himself. Someone else compiled rules based on the AI coding shortcomings he highlighted: incorrect assumptions, excessive code, and changes to unrelated code.
  • The repository has no separate LICENSE file, but says 'MIT' at the end of the README. For that reason, we will only summarize the rules here rather than reproduce the full text. See the repository above for the original.

The 4 rules, summarized

1. Think first: Do not make arbitrary assumptions. If something is ambiguous, ask rather than choose an interpretation on your own. 2. Keep it simple: Do only what was requested, with only as much code as needed. 3. Change only what is necessary: Leave neighboring code, comments, and styles alone. 4. Work toward a goal: Instead of just 'fix it,' define criteria that tests can verify, and work until they pass.

Follow Along: Add It to Your Project

You will need: a Windows PC with Claude Code installed, and a project folder to work in. (If you have not installed Claude Code yet, we plan to cover that in the next column.)

Step 1. Click the Start (시작) button and type PowerShell to open a blue (or black) window. This is called a 'terminal.'

Step 2. Navigate to your project folder. For example, if it is a folder named my_project on your desktop, type the following and press Enter.

cd $HOME\Desktop\my_project

Step 3 (✅ Hands-on). Enter the following line exactly as shown, then press Enter. This command downloads the repository's CLAUDE.md file into your folder under the same name.

Invoke-WebRequest https://raw.githubusercontent.com/multica-ai/andrej-karpathy-skills/main/CLAUDE.md -OutFile CLAUDE.md

Step 4. Check the file. If you enter dir CLAUDE.md and see a CLAUDE.md file of about 2,357 bytes, it worked (the size we downloaded on 10/28). You can also open it in Notepad and check whether the first line is # CLAUDE.md.

Step 5. Run claude in that folder as usual and give it a task. Claude Code automatically reads the CLAUDE.md in the folder where you launch it (📄 according to the official Claude Code documentation). In our tests, simply adding the file changed its behavior under condition B.

Common problems and solutions

  • If the folder already has a CLAUDE.md: The command in Step 3 overwrites the existing file! First make a copy of the existing file, with a name such as CLAUDE_backup.md, then append the downloaded content to the existing file (📄 the README also says to 'append to your existing file').
  • If 'Invoke-WebRequest' fails: Check your internet connection. Alternatively, open the repository in your browser, go to CLAUDE.md → the 'Raw' button → right-click and choose 'Save as (다른 이름으로 저장).' Make sure the filename does not end up as CLAUDE.md.txt.
  • If you want to use it across all projects (📄 documentation only; we have not tried this): The README also explains how to install it as a plugin within Claude Code using /plugin marketplace add and /plugin install (the README's original commands: enter /plugin marketplace add forrestchang/andrej-karpathy-skills, then /plugin install andrej-karpathy-skills@karpathy-skills).

How Did We Test It? All Original Prompts Included

  • Test code: our own cart.py (54 lines, 7 functions) + test_cart.py (6 tests). We deliberately included 1 percentage-coupon bug (a 10% coupon subtracts 10 won, the South Korean currency) and an unused legacy function (_old_round).
  • Conditions: A = no CLAUDE.md, B = Karpathy CLAUDE.md copied to the top level of the folder.
  • Execution: Claude Code 2.1.303 in non-interactive mode (claude -p), model claude-opus-5-5, default settings, identical permissions (read, edit, write, and run Python tests only; no deletion or internet access), with each run performed once in a fresh copy of the folder. We ran the tests in a separate folder to keep our own workflow rules file out of the experiment.
  • Evaluation: lines changed in cart.py (compared with the original), the 6 original tests, separate hidden tests, whether it asked first (0 code lines changed + a question), and time and cost (values displayed by Claude Code).

Exactly what we sent:

  • Task 1 (feature addition): Please add an update_qty(cart, name, qty) function to cart.py to change an item's quantity in the shopping cart.
  • Task 2 (bug fix): I applied a 10% coupon, but the total looks wrong. Please fix it.
  • Task 3 (ambiguous request): Please make the receipt look a bit nicer.

Result 1. Feature Addition: 14 Lines → 10 Lines

  • A: 14 lines in all 3 runs. In all 3 runs, it also decided on its own to remove an item when its quantity was set to 0. That behavior was not requested (though it did disclose in its response that this was its own decision).
  • B: 10 lines in all 3 runs. It chose to raise an error for values of 0 or less, just like the existing add_item. It followed the approach already used in the code.
  • Hidden tests (3 checks, including quantity 3 → 5 and a subtotal of 4,500 won after the change): all 6 runs passed 3/3.
  • Runs that also added new tests: A 2, B 3. Average time: A 25.1 seconds, B 29.2 seconds.

Actual execution screen for feature addition B (Karpathy rules), run 3: cart.py +10 lines, hidden tests 3/3

Result 2. Bug Fix: No Difference

  • All 6 runs changed only the same line in cart.py (2 lines changed = 1 deleted and 1 added) + 6 lines of tests added.
  • The corrected expressions differed only in form: A used amount * (100 - value) / 100, while B used amount - amount * value / 100. The results were the same.
  • Hidden tests: with a 10% coupon, 10,000 won → 9,000 won; a cart total of 5,500 won → 4,950 won → 5,445 won including tax. All 6 runs passed.
  • All 6 runs left the unused legacy function _old_round untouched.
  • The average cost was slightly higher for B, which also read the rules file (A 0.095 dollars, B 0.121 dollars).

Result 3. Ambiguous Request: Did It Ask First?

  • A: It made changes immediately in all 3 runs. Lines changed: 33·37·31. It added alignment, commas, and subtotal and tax lines, and independently updated the expected string in the existing receipt test to match the new format in all 3 runs.
  • B, runs 1·2: It asked first without changing a single line of code. It laid out the current output, a proposed format, and questions such as 'Is this direction acceptable? / Should the labels be in Korean? / May I update the tests?' It also pointed out that the tests compare the entire receipt string exactly.
  • B, run 3: It made changes immediately without asking. 13 lines. It stated that it had interpreted 'look nicer' narrowly as alignment and display formatting, and also changed the expected test string.
  • Average time: A 47.8 seconds, B 23.5 seconds (shorter because some runs stopped after asking questions).

Limitations: What Did Not Work and What Depends on Context

  • With only 3 runs per condition, we cannot generalize. Results may differ with other code, models, or interactive mode.
  • In non-interactive mode, the run ends when Claude asks a question. In actual use, there would be another exchange to answer it.
  • What it already did well without the rules: In all 12 runs that were not bug-fix tasks, it independently found and reported the hidden coupon bug (without fixing it). It also left the unused legacy code untouched in all 18 runs. That left no opportunity for the 'change only what is necessary' rule to demonstrate an effect in this test.
  • If you want an immediate result, 'asking first' may simply mean an extra step for you.
  • Recording note: The recording tool failed to capture the window during runs 1·2, so those runs were not recorded. We therefore recorded all 6 executions in run 3 as they happened. For the scene where B asked first (run 1), we reopened the saved log file on screen and recorded it. All figures are taken directly from the saved logs.

Bottom Line: Should You Install It?

  • If you tend to write short, loosely specified requests, it is worth trying. It encourages asking first when something is ambiguous.
  • If you already write detailed requirements, do not expect a major difference.
  • If you add it, just make sure you do not overwrite an existing CLAUDE.md.
