At a Glance

  • What is it? A skill that adds design commands (polish, bolder, critique, audit) to coding agents—AI tools that write code for you—such as Claude Code, Cursor, and Codex CLI. It also includes a detector with 62 rules for spotting common UI patterns.
  • Bottom line: We successfully completed a project-scoped installation and 1 sample scan on Windows x64 (verification level: verified, but limited to installation-level checks). The sample produced 9 findings (8 major, 1 informational) across 5 distinct rules.
  • Limitations: We did not try modifying the interface with polish, so we will not claim that it "improves the design."

A short video covering the same material: YouTube Short

Before You Start

  • Cost: The skill and detector are free and open source. They use the Apache-2.0 license and were created by Paul Bakaus. However, edits made with commands such as polish require an account with your coding agent and count toward its usage.
  • Account: For installation and file scanning alone, we did not need to sign up, pay, provide an API key (a key used to access a service), or have an AI account.
  • Node.js: You need at least 18.19.0. Node.js is a JavaScript runtime and is required to use npx commands. The official package.json for the 4.8.0 tag specifies >=18.19.0. However, Node.js 18 has already reached end of life (EOL). For a new installation, download an LTS (Long-Term Support) version from nodejs.org. Then open a new PowerShell window and check the version with node --version. We used the v26.5.0 installation already on our PC.
  • OS: Windows x64 is the only platform we tested directly. The official list also includes engines for macOS and Linux, but we did not run them.
  • Internet: Required for the initial downloads of the package, skills, and engine.
  • Version: This article covers skill-v4.8.0. It is an update, not the initial release. It was published at 2026-10-26 23:41(UTC), which is 10/27 at 8:41 a.m. in Korea (release notes).

Installation

1. Prepare a project folder ✅ Tested directly ① Create a folder for a practice web project. In PowerShell (the Windows command shell), create the folder with mkdir impeccable-test, then move into it with cd impeccable-test. The folder name is just an example. ② The official documentation only says to "start from the project root." It does not specify a particular success message.

2. Run the installation command ✅ Tested directly ① Pin the version and install only within the project. Do not add -g or --global (global installation).

   npx --yes impeccable@4.8.0 install -y --providers=claude,cursor --scope=project

② Our run finished in 5.806 seconds with exit code 0 (successful completion). It installed npm package 4.8.0 and engine 0.1.18, and created skill, agent, and hook files in the project’s .claude and .cursor folders. ③ If the first run fails, see 'Common Problems' below. Our first attempt failed too.

3. Interactive installation (optional) 📄 Based on the official documentation ① Entering only npx impeccable install, without pinning a version, starts an installation that walks you through a series of questions. ② It displays a list of detected coding tools. You then choose which tools to use and the installation scope (this project only or global). For supported tools, it also offers an automatic design-checking hook, with yes as the default. The documentation does not specify the button labels.

4. Inspect the hooks, then reload your tool ✅ Tested directly (file inspection only) ① Open the generated files .claude/settings.local.json and .cursor/hooks.json and read their contents. A hook is a command that runs automatically at a defined point. ② Once you have checked them, reload your coding tool. This installation does not install Claude Code or Cursor themselves. You do not need them for file scanning alone, but you must set up a coding tool separately to make edits with commands such as polish. Because the installation is project-scoped, open the project where you installed it. If the new skills do not appear, restart the tool and enter /impeccable in chat to check whether the command list appears. This part follows the official instructions; we did not go as far as launching the coding tool.

5. Install as a Claude Code plugin (alternative) 📄 Based on the official documentation ① Enter /plugin marketplace add pbakaus/impeccable in Claude Code. Then install Impeccable from /plugin. A plugin is an add-on that provides extra functionality. ② We checked this only in the documentation and did not run it ourselves.

How to Use It

1. Scan files ✅ Tested directly ① In the project folder, create a folder with mkdir src, place the HTML, CSS, JSX, or TSX files you want to scan in src/, then run the command. We used a small HTML/CSS example for a fictional company that we wrote ourselves. Scanning different files may produce different finding counts and rule types.

   npx --yes impeccable@4.8.0 detect --json src/

② The exit codes mean the following: 0 means no major findings, 2 means major findings were detected, and 1 means the scan failed. We got 2. That is a valid result indicating that findings were detected. ③ The same finding may appear multiple times in the output. Do not assume that the number of entries equals the number of problems.

2. View the rule list ✅ Tested directly

   npx --yes impeccable@4.8.0 detect --list-rules --json

② This lists 62 unique rule IDs. Our result also contained 62.

3. Scan a rendered page (URL) 📄 Based on the official documentation ① Rules that require inspecting the rendered page, such as contrast and small text, are checked only when you pass a development server URL to detect. Chrome, Chromium, or Edge must be installed, and you can specify the browser with IMPECCABLE_BROWSER if needed (detector documentation). ② A file scan alone does not cover these rules. We did not try a URL scan.

4. Ask the agent to polish the design 📄 Based on the official documentation ① Enter /impeccable init in chat, followed by /impeccable polish <target>. In Codex, use the $impeccable syntax. ② This step counts toward your account usage. We did not run it this time.

Our Hands-On Results

The verification level is verified. However, that assessment applies only to installation in an isolated folder, help output, version checks, and 1 sample scan. These checks were performed as of 2026-10-30.

Here is what happened, in order.

1. The first attempt to display help failed. The package downloaded over 21.788 seconds. However, The system cannot find the path specified. appeared, and the process ended with exit code 3. That was unexpected. 2. Adjusting the paths resolved it. We set the Node path and cache path only for that shell session, then ran it again. It succeeded in 2.113 seconds. We did not change the system PATH. On the first run, we had invoked Node using its full path without adding it to PATH. If you encounter the same error, try the following. Replace the text in angle brackets with your own folders, and run all three lines in the same PowerShell window. These settings disappear when you close the window.

   $env:PATH = "<Node.js folder>;" + $env:PATH
   $env:npm_config_cache = "<cache folder>"
   npx --yes impeccable@4.8.0 --help

For our retry, we also added --offline to reuse the cache downloaded during the first run. Because this was an isolated test, we also changed paths such as HOME and TEMP. We therefore did not test the settings individually to determine which one made the difference.

3. We installed it within the project. This took 5.806 seconds. That does not include the time spent on the initial failed attempt. 4. We scanned the sample. This was a small HTML/CSS example for a fictional company that I wrote myself, not an interface created by Claude Code. The scan took 0.961 seconds. This measures only the time to scan a small file after installation was complete.

  • Result: 9 entries (8 major, 1 informational)
  • 5 distinct rules: side-tab, gradient-text, overused-font, skipped-heading, bounce-easing

What to check when trying similar tools

  • Whether installation is project-scoped or global
  • Which hook files are created and what they contain
  • Whether the exit code means 'findings detected' or 'scan failed'
  • Whether rendered-page rules were checked or only a file scan was performed

Common Problems

  • The system cannot find the path specified. (exit code 3) — This is where we got stuck. We checked the log to confirm that the package had downloaded. Then we adjusted the Node path only for that shell session, and it worked.
  • A security error says npx.ps1 cannot be loaded — We did not encounter this error. It can occur when PowerShell’s execution policy blocks script files (.ps1) (Microsoft documentation). Before relaxing the execution policy, try replacing only npx with npx.cmd in the same command. We did not test this method ourselves.
  • You get exit code 2 — This is not an error. It means there are major findings. Exit code 1 indicates a scan failure.
  • No contrast or text-size findings appear — These may not appear in a file scan. You need to scan the rendered page using a development server URL and a supported browser.
  • You are concerned about hooks — The official documentation includes a warning. Hooks can run independently of model approval and may download the engine. Do not apply them casually to unfamiliar repositories.
  • You cannot capture the terminal — We also failed to capture the original terminal. That is why the log image above shows a redisplay of the saved execution log.

Wrap-Up

Impeccable 4.8.0 installed cleanly within a project on Windows x64. The file scan finished in under 1 second without an account. However, we verified only its role as a "detector that flags common patterns." Whether it actually improves a design remains to be tested by running polish.
