Introduction

Sometimes we transfer a date calculated by AI into a work schedule or put the output of code it has explained into development documentation. When an answer is short and confident, it is easy to skip verification. But if even one date or number is wrong, the documents built around that answer need to be reviewed too. Confidence and correctness must be checked separately.

The experiment on October 24, 2026 compared this verification process. According to the records, all three models scored 3 on the first set. On the harder second set, GPT and Claude each scored 3. No response was obtained from Gemini, so all three questions remained unverified. The conditions were 1 attempt at each identical question, with 0 retries.

However, the published questions and answer key belong to the first set, while the individual responses and grading table belong to the second. Without making that distinction clear, we would be comparing answers to different questions in a single table. This is the first thing to check when reading these results.

Experiment Design

The questions covered three tasks: date calculation, letter counting, and Python output. The aim was to check the accuracy of short answers rather than the ability to write long passages.

The first set's questions and predetermined answers were as follows.

  • The date and day of the week 365 days after the start (0 hours) of February 29, 2024: 2025-02-28, Friday
  • onomatopoeia — number of occurrences of o: 4
  • print(len({1, 1.0, True, '1'})) — output: 2

Setting the answers in advance helps reduce the temptation to change the grading criteria after seeing the responses. For dates, the criterion is how many days are added to the starting time; for letters, exactly what is being counted; and for code, what value is actually printed. Natural-sounding language does not earn points.

There are clear reasons for choosing these questions. Calendars have leap years, words contain repeated letters, and code can contain items that look different but are treated as the same value. These are all situations where a quick glance can suggest an answer different from the one verification produces.

The model labels were GPT-6.1 Sol High, Claude Opus 5.5 Medium (중간), and Gemini 4 Argon. Their answers were compared by submitting the same questions once to each model, without retries. The experiment summary states that after all models answered the first set correctly, a harder second set followed.

Why These Results Occurred

The trap in the first question of the published first set is that “365 days later” can easily be mistaken for “the same date next year.” The starting date is February 29, 2024, a leap day. Adding exactly 365 days gives February 28, 2025, which is a Friday. A complete answer requires checking both the date and the day of the week.

The second question tests the distinction between recognizing a familiar word and counting its letters. Splitting onomatopoeia into individual letters gives o n o m a t o p o e i a. The letter o appears in the first, third, seventh, and ninth positions, for a total of four. Marking letter positions makes this easier to verify than reading the word in chunks based on pronunciation.

For the third question, simply counting the items written inside the braces gives the wrong answer. A Python set does not store duplicate values that it treats as equal. Here, the number 1, the floating-point number 1.0, and the Boolean True are treated as the same value. The string '1' is a separate value. The set therefore has a length of 2.

This explanation applies only to the published questions from the first set. Without the original questions for the second set, we cannot explain its specific traps or the models' solution processes. Nor can we conclude that the two models used the same method simply because their final answers matched.

Conclusion

The results to note in this comparison are that all models answered the first set correctly, GPT and Claude tied on the second set, and Gemini remained unverified. In practical work, it is worth checking the following alongside the scores.

  • Confirm that the questions and responses belong to the same set.
  • Verify dates using a fixed starting time and number of days to add.
  • Count letters by separating them or marking their positions.
  • Verify code output by running the code, and retain the original response.
  • Record missing responses separately from incorrect answers.

Each question was attempted 1 time, with 0 retries, and each set contained 3 questions. This small experiment alone cannot establish which model is generally better.
