Trying 5 New AI Tools on Windows: Gemini Canvas, OpenScreen, earshot, diagram-design and HyperFrames

2026-10-26 · SaeAI Lab Notes (새AI실험노트) · Hands-on installation log (measured 10/19~10/23)

Grading result: 'Total score: 100 points (Pass)' (actual screen, 10/19)

Test environment and limitations · Hands-on installation log (measured 10/19~10/23) · These results document one attempt per tool on a single Windows PC. Results may differ on other PCs or versions.

We installed and ran 5 new AI tools that have been getting attention lately on a single Windows PC. The results, up front: 2 worked right away, 2 worked with conditions, and 1 failed. This guide covers the requirements → steps → what success looks like → where things get stuck for each tool, so even first-time users can follow along.

Read This First: How We Tested

  • Test dates: October 19~23, 2026, using a single Windows PC, our existing accounts and a separate test folder.
  • ✅ Tested firsthand = we actually ran it on our PC and checked the results.
  • 📄 Based on official documentation = described in the official documentation, but not tested by us.
  • Each time reported here is from a single measurement. Times will vary with your computer and internet speed.
  • We made no payments and signed up for no new accounts.

Results at a Glance

  • Gemini Canvas: worked right away (no installation; runs directly on the web)
  • OpenScreen 2: worked (free recorder; automatic zoom worked, but demo skill installation failed)
  • earshot: conditional (about 7 minutes to install + a model of about 1.1GB)
  • diagram-design: conditional (worked only by pasting the instructions into Claude on the web)
  • HyperFrames: failed on this PC (0 MP4 videos)

3 Terms to Know Before You Start

  • Terminal (PowerShell): a black window where you type commands. Click the Start (시작) button and type PowerShell to open it.
  • Test folder: when installing a new tool, create an empty folder such as ai_test somewhere like your desktop, and keep your testing inside it. If something goes wrong, you can clean up by removing the whole folder.
  • Git, Node.js and Python: these are prerequisite programs often needed when installing developer tools. Each tool has different requirements.

1. Gemini Canvas: Turn a Single PDF into a Quiz App (✅ Tested Firsthand, 10/19)

Requirements: a Google account and a web browser. No installation or API key needed.

Step 1. Open gemini.google.com in your browser and sign in with your Google account.

Step 2. To the left of the input box, click the + button (+ 버튼) → More tools (도구 더보기) → Canvas. If 'Canvas' appears in the input box, it worked.

Step 3. Click the + button → Upload files (파일 업로드) to upload 1 PDF. Do not upload a PDF containing personal information. We created our own fictional company security training material for this test.

Step 4. Enter and send this prompt: Make a quiz app from this PDF. Include 5 questions, with grading and a score after I select my answers.

Canvas selected + PDF attached + the prompt we sent (actual screen, 10/19)

Step 5. Wait 1~2 minutes. Our quiz app was ready after about 90 seconds (checked every 5 seconds; measured once).

Step 6. Answer the questions in 'Preview' (미리보기), then click the Grade (채점) button. If you see a score and the correct answer for each question, it worked. We answered all 5 questions correctly and got 'Total score: 100 points (Pass)'. Incorrect answers also displayed explanations and references to the relevant rules.

Grading result: 'Total score: 100 points (Pass)' (actual screen, 10/19)

Problems and solutions (📄 based on official help)

  • If you see 'You have reached the limit for chats containing files': this is an upload limit for a given period. Wait and try again later.
  • If you see 'The upload is too large…': try splitting it into smaller files and uploading those.
  • If a shared link will not open in the Gemini mobile app: shared canvases must be opened on the gemini.google.com website.

Cost: the official pricing page says free accounts can use Canvas too (usage limits vary by plan). However, we tested it only with a Google AI Pro account; we did not verify it with a free account.

2. OpenScreen 2: A Free Screen Recorder That Automatically Zooms In Where You Click (✅ Tested Firsthand, 10/20)

Requirements: Windows 10 (1903 or later) or 11. Free (MIT license), with no watermark.

Step 1 (📄 officially recommended method). Enter winget install --source msstore OpenScreen in the terminal to install the Microsoft Store version. Alternatively, download Openscreen.Setup.<version>-x64.exe (e.g., Openscreen.Setup.2.1.2-x64.exe) from Releases at github.com/getopenscreen/openscreen and run it. If a blue warning screen appears because the app is unsigned, click 'More info (추가 정보) → Run (실행)'.

For our test, we extracted just the app from the official installer (v2.1.2) and ran it in the test folder to avoid installing it on the system. Downloading took 6.4 seconds, and extracting the app took 9.1 seconds.

Step 2. In the app, select a window or the entire screen to record. Record while clicking the areas you want to show, then stop. We recorded a test window for 10 seconds and clicked buttons 3 times.

Step 3. Turn on Automatic zooms (자동 줌) and export as MP4. Automatic zoom works without an API key. Our MP4 was ready in 9.6 seconds. Success means it zooms toward the clicked button at around the 4-second mark, then returns to the full-screen view at the end.

MP4 exported by OpenScreen: automatically zooming toward the clicked button (10/20)

Step 4 (optional). Connect to Claude Code: if you installed the .exe version, enter claude mcp add openscreen -- "%LOCALAPPDATA%\Programs\Openscreen\Openscreen.exe" mcp in the terminal. If Connected appears in claude mcp list, the connection worked. Registration took us 0.8 seconds, and checking the connection took 1.9 seconds. For the Store version, the official instructions say to enable AI settings → MCP server in the app and use the command shown on screen.

Problems and solutions (✅ issues we actually encountered)

  • Installing the demo skill with npx skills add getopenscreen/openscreen --skill openscreen-demo failed with 'spawn git ENOENT'. This happened because Git was not installed on this PC. You need to retry it on a PC that has Git and Node.js installed.
  • What we did not test: converting speech to subtitles (requires an initial model download of about 264MB), in-app AI editing (requires your own API key), or having Claude Code perform actual edits.

3. earshot: A Tool That Uses AI to Listen to and Identify Sounds (✅ Tested Firsthand, 10/21 · Conditional)

Requirements: Python 3.10 or later and ffmpeg. Free (MIT); runs on a CPU without a GPU, and its core features need no API key (according to the official documentation).

Step 1. Enter python --version and ffprobe -version in the terminal and check that both return version numbers. If not, install them first.

Step 2. At github.com/Leonxlnx/earshot, use Code → Download ZIP, then extract it into your test folder. If you have Git, you can also use git clone https://github.com/Leonxlnx/earshot. We used the ZIP because Git was not installed.

Step 3. In PowerShell, enter Set-Location "<path to that folder>" to move into the extracted folder containing pyproject.toml, then create a virtual environment: python -m venv .venv

Step 4. Install the CPU version of PyTorch first: .\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu (154 seconds for us)

Step 5. Install earshot: .\.venv\Scripts\python.exe -m pip install -e . (We used .[mcp] to include MCP support, which took 260 seconds. Together with Step 4, this took about 7 minutes.)

Step 6. Run diagnostics: .\.venv\Scripts\python.exe -m earshot doctor --load The first run downloads a sound model of about 1.1GB, so it takes some time.

Step 7. Test an audio file: .\.venv\Scripts\python.exe -m earshot describe .\sample-doorbell.ogg We supplied a 3.7-second doorbell sound effect (CC0, Wikimedia Commons). After 51.49 seconds, the result included 'a doorbell'. If you see this, it worked.

Excerpt from earshot's actual identification log: 'a doorbell' after 51.49 seconds (10/21, log redisplayed in larger text)

Things to keep in mind

  • We tested exactly 1 sound, so we cannot claim any accuracy percentage.
  • The official documentation also says it cannot judge preferences, emotions or the content of speech.
  • The official instructions also explain how to direct temporary files and caches to the test folder. If you want to keep your PC tidy, read the installation section of the official README as well.

4. diagram-design: A Skill That Draws Report Diagrams from Written Descriptions (✅ Tested Firsthand, 10/23 · Conditional)

Requirements: a Claude account (web or Claude Code). The skill itself is free (MIT), but AI usage costs depend on the service plan you use. The official README says it supports 45 diagram types, but we tested only 1 type: a flowchart.

Our three attempts

  • Attempts 1 and 2: we placed the skill folder in Claude Code and requested a 'flowchart of a fictional online store's order process' → our own safety restrictions blocked file writing, leaving 0 output files (159 seconds, 145 seconds). The command exited normally, but we counted these as failures because there were no files.
  • Attempt 3: we pasted the official instructions (SKILL.md) and reference documents directly into Claude on the web, then made the same request → the flowchart was ready after about 177 seconds. Downloading it as HTML produced 1 file (10,854 bytes) with no external URLs.

Follow along: the method that worked for us

Step 1. At github.com/cathrynlavery/diagram-design, use Code → Download ZIP and extract it.

Step 2. Open SKILL.md inside the skills/diagram-design folder, along with the relevant documents in the references folder (the style guide, flowchart instructions and so on).

Step 3. Paste their contents into a new conversation at claude.ai and ask: Use this skill to draw a flowchart for a fictional online store: order→payment→shipping→delivery→returns/refunds. Use system fonts for Korean text, and produce a single HTML+inline SVG file with no external requests.

Step 4. Once the result (artifact) appears, select Export (내보내기) → HTML from the menu to save it. If the flowchart appears in your browser, it worked.

The flowchart HTML created in Claude on the web, opened in a browser (10/23, fictional data)

📄 Based on official documentation (not tested by us): in tools such as Claude Code and Cursor, the standard installation method is npx skills add cathrynlavery/diagram-design. You must allow file-writing permission for output files to be saved.

5. HyperFrames: Turn HTML into MP4 Video (✅ Tested Firsthand, 10/22 · Failed on This PC)

Requirements: Node.js 22 or later, FFmpeg and a working Chrome installation. Free and open source (Apache-2.0).

The steps we took

Step 1. In the terminal, run npx --yes hyperframes@0.8.185 init my-video --non-interactive (📄 the official command; on our PC, the npx launcher reported a path error, so we ran the same command directly with node) → successfully created a new project folder (downloading the program and displaying help: 11.68 seconds; new project: 0.83 seconds).

Step 2. Add a title and animation to index.html in the my-video folder.

Step 3. Run npx --yes hyperframes@0.8.185 render --output renders/test.mp4 → this is where it failed.

Excerpt from the HyperFrames render failure log: EPERM, ETIMEDOUT, 0 MP4 files (10/22)

Where it got stuck (✅ issues we actually encountered)

  • Attempt 1: automatic installation of Chrome for rendering stopped with an 'EPERM (permission denied)' error.
  • Attempt 2: we specified the existing Chrome installation with HYPERFRAMES_BROWSER_PATH, but Chrome did not respond and the process timed out.
  • Result: 0 MP4 files. We could not determine whether security software or a permissions issue caused the failure, and we deliberately left security settings enabled. Do not disable security features just to make it work.
  • Passing static checks (lint) does not mean a video has been created. Success means an MP4 actually appears in the renders folder and plays.
  • 📄 According to the official information, the native Studio app for Windows is still listed as 'Coming soon'.

A Checklist for Installing New AI Tools

1. Start with web tools that need no installation.

2. Check the official README first for prerequisites such as Git, Node.js or Python.

3. Install only inside a separate test folder.

4. Rather than relying on messages such as 'Done' (완료) or 'Success' (성공), check that an output file really exists and open it yourself.
