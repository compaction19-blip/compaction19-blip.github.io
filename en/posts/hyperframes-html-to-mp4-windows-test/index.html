At a Glance

  • HyperFrames is an open-source (Apache-2.0) video tool released by HeyGen. It turns HTML, CSS, and seekable animations into MP4 files using headless Chrome (Chrome running without a visible interface) and FFmpeg.
  • We tested v0.8.185 on a Windows PC on 2026-10-22. Project creation and static analysis (lint) succeeded, but MP4 rendering—exporting a video file—failed on both attempts. Our verification level is partial.
  • The local rendering engine is free. However, AI coding agents, cloud services, and optional features such as voice and avatars may incur separate costs.

What to Check Before Starting

  • What this tool does: This is not a tool that automatically turns any ordinary webpage into a video. It is a framework in which you write video-specific HTML yourself, or have an AI agent create it, then render it with a local CLI (a command-line program). AI agent integration is optional. (Official repository)
  • Requirements: You need Node.js 22 or later (a JavaScript runtime), FFmpeg (a video conversion tool), and a working Chrome/Chromium installation. It also uses local disk space, CPU, and RAM. An internet connection may be needed to install a browser automatically or download external scripts.
  • Pricing and accounts: The license is Apache-2.0. There are no per-render fees or limits on the number of commercial users. Local rendering does not use HeyGen credits. Our tests (help, init, and render) required no payment, registration, API key entry, or HeyGen login. Coding agent subscriptions and optional hosting, voice, avatars, and generated media may cost extra. (Quickstart)
  • OS: The CLI runs on Windows (we verified it through init in our test). The separate Studio desktop app is available to download only for macOS and Linux. Windows and Windows arm64 are listed as Coming soon. This app is different from the preview you open in a browser.
  • Recent updates:
  • v0.8.160 (2026-10-15): Fixed the first render on Windows to wait until newly downloaded browser and FFmpeg files are accessible.
  • v0.8.185 (2026-10-21; shown as Oct 22 on the Tags page in Korean time): Added capture motion blur as an opt-in feature. cloud render --resolution 4k also gained support for transparent MOV and WebM. This was not the update that first introduced 4K support.
  • Interest: On 2026-10-22, we saw 69,371 total stars and a weekly increase of 5,740 on the GitHub weekly trending page. According to the official npm API, downloads from 2026-10-12 to 2026-10-18 totaled 510,551. Both figures change over time, and neither is a user count.

Installation

Enter the commands below in a terminal such as PowerShell—a window where you type commands.

1. Check the environment — 📄 Based on the official documentation

npx hyperframes doctor
  • What success looks like: The official example shows 'All checks passed' and a pass indicator for each item. The version numbers in the example are not minimum requirements.
  • We did not run this command. (CLI documentation)

2. Create a project — 📄 Based on the official documentation / ✅ Tested directly with additional options

npx hyperframes init my-video
  • What success looks like: A new video project is created from an example. The documented default example is 'centered Inter blank'.
  • Here is what we actually entered.
$env:HYPERFRAMES_SKIP_SKILLS="1"; $env:DO_NOT_TRACK="1"; npx --yes hyperframes@0.8.185 init my-video --non-interactive
  • Result: It took 0.83 seconds and created 6 files. The exit code was 0.
  • If you get stuck: The --skip-skills option is currently ignored. To skip installing agent skills, we had to use the HYPERFRAMES_SKIP_SKILLS=1 environment variable.

3. Move into the project folder — ✅ Tested directly

cd my-video
  • The documentation does not describe a specific success message.

4. (Optional) Claude Code plugin — 📄 Based on the official README; we did not install it

claude plugin marketplace add heygen-com/hyperframes
claude plugin install hyperframes@hyperframes
  • Once installed, invoke it with /hyperframes:hyperframes. We did not run it this time because our rule was not to change account settings.

How to Use It

1. Write the video content — ✅ Tested directly

  • In our test, index.html defaulted to a 10-second Title placeholder.
  • We changed the title to "HTML → MP4", shortened the duration to 5 seconds, and added a GSAP fade-up animation. Aside, not a person, edited this HTML. It was not created with the Claude plugin.
  • When backing up the original, save it with the .html.bak extension. This prevents it from being detected as a duplicate root composition.

2. Preview — 📄 Based on the official documentation

npx hyperframes preview
  • What success looks like: The video composition opens in HyperFrames Studio. The output includes a Studio project URL and a server URL.
  • The default port is 3002. However, use the URL actually shown in the output.

3. Static analysis — ✅ Tested directly

npx hyperframes lint
  • What success looks like: The check results appear. Errors must be fixed before rendering; Warnings indicate potential problems.
  • We added the --json option. The final result was ok true, 0 errors, and 0 warnings.

4. Browser check — 📄 Based on the official documentation

npx hyperframes check
  • If there are lint errors, the browser check is skipped. If browserSkipped is true in the JSON report, the check has not passed, even if layout, motion, and contrast are empty.

5. Render — 📄 Based on the official documentation / ✅ Attempted, but failed

npx hyperframes render
  • The command we ran was npx --yes hyperframes@0.8.185 render --workers 1 --output renders/test.mp4.
  • How to confirm success: The output file must actually exist. You should also use ffprobe to check its duration, resolution, and frame count. We did not reach this stage.

Common Sticking Points

  • npx fails with "The system cannot find the path specified" (exit 3): On our PC, Aside's npx wrapper conflicted with sandbox environment variables. Running npm's npx-cli.js directly with the existing node.exe allowed the download and help command to work.
  • EPERM rename error during render: This occurred while automatically installing chrome-headless-shell 152.0.7977.30. We could not determine whether security software, permissions, or a file lock caused it.
  • Still fails when an existing Chrome installation is specified: We set HYPERFRAMES_BROWSER_PATH only in the current shell and tested again with the existing Chrome installation (without changing system settings). On our PC, the chrome.exe --version response timed out. We stopped there. We did not disable security features, run as administrator, or reinstall.
  • Lint reports multiple_root_compositions: The backup file index.original.html was also being recognized as a root. Renaming it to .html.bak resolved the issue.
  • --skip-skills does not work: Use the HYPERFRAMES_SKIP_SKILLS=1 environment variable.
  • No Studio app for Windows: It is still listed as Coming soon. Use the CLI and preview.

Conclusion

HyperFrames is a free local rendering engine with a clear approach: building videos in HTML. On our Windows PC, installation and project creation worked, but we got stuck at the browser preparation stage and could not create an MP4. These results do not support saying that it can produce a video straight away on Windows. If we successfully render one, we will document it then.
