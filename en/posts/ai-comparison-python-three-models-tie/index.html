3 Next to 100? Three AIs Tie Again in a Retest

Introduction

When an AI gives you the output of a short piece of code, it is tempting to use the answer as is. Developers want to spend less time reviewing, and office workers want to finish automation tasks quickly. But treating a fluent answer as an accurate one can carry a misunderstood rule into the next task.

On 2026-10-20, I gave GPT, Claude, and Gemini the same three Python output questions. All three answered every question correctly. I then tested a harder set in new conversations, with the answer key fixed in advance, but all three models again scored 3 points. There is no winner in this experiment.

What matters here is not the ranking, but why the code produces those outputs. Why does reversing the order of addition change the value? And why can reading variables with the same name produce different numbers?

Experiment Design

The basic set consists of three questions covering addition methods, execution order in multiple inheritance, and variable references inside a class. Each question asked for the exact single line of standard output, without an explanation. The test focused on whether the output was correct, rather than how convincing a lengthy explanation sounded.

In the first question, P, which inherits from the integer type, was defined to always return 100 from __add__. The code then printed P(1) + 2, 2 + P(1), and P(1) + P(1) together.

In the second question, D inherits from B, C, while B and C each inherit from A. Each initialization method calls super() before appending its own letter to a string. The third question sets up an outer x = 1 and a class-level x = 2, then compares the results of a regular list and a list comprehension.

I saved the answer key to a file before submitting the basic set. To avoid changing the scoring criteria after seeing the responses, you need to decide in advance what counts as correct. For each set, I sent the same questions once to each model, with no retries. The harder set was tested separately in new conversations.

Why the Code Produces These Results

The trap in the first question lies in the roles of the operands on either side of the addition sign. In P(1) + 2, the __add__ method overridden by P is used, producing 100. P(1) + P(1) also produces 100 for the same reason.

By contrast, the left operand in 2 + P(1) is a regular integer. Having a P object on the right does not mean that object's __add__ is simply called. This code does not separately override addition in the reverse direction, so it produces the integer addition result, 3. The result is therefore 100 3 100, with only the middle value differing.

The second question becomes confusing if you think of super() as simply meaning “my immediate parent.” In this structure, the method lookup order is D → B → C → A. The super() in B also follows this order, continuing to C.

However, each letter is appended only after its super() call finishes. The innermost A creates "A", and as the calls return, C, B, and D append their letters in turn. The final string is ACBD. It is easier to understand if you distinguish the order in which calls are entered from the order in which their work finishes.

The third question tests how the same x can be read from different scopes. The y = [x] evaluated directly in the class body reads the class-level x = 2 defined earlier. Therefore, y is [2].

However, the x read inside the comprehension in z = [x for _ in range(1)] does not access the class body's variable in the same way. Here it reads the outer x = 1, producing [1]. Printing both results together gives [2] [1].

All three models answered correctly on all three distinctions. However, because the prompt requested only the output, this experiment did not establish what reasoning process the models used internally.

Conclusion

The conclusion from this AI comparison is clear: both the basic set and the harder retest ended in a tie. This record, at least, does not support saying that any particular model is better at solving Python output questions.

In practical work, a verification process is more useful than focusing on the model's name.

  • Set the correct answers and scoring criteria before receiving responses.
  • Give each model the same code and output requirements.
  • Run executable code yourself and compare its output with the answer.
  • Check operator direction, call order, and variable scope separately.
  • If the result is a tie, record that no difference was found and broaden the evaluation.

Each set involved 1 attempt at 3 questions, with 0 retries of the same questions. These results alone are not enough to judge overall coding ability or relative performance on other tasks.

Original Prompt and Actual Responses

I sent the following questions to each of the three AIs exactly 1 time.

Give a brief, numbered answer to each of the 3 questions below.
1. In Python 3, write exactly the single line of standard output produced by the code below. Do not include an explanation.
class P(int):
    def __add__(self, other):
        return 100
print(P(1) + 2, 2 + P(1), P(1) + P(1))
2. In Python 3, write exactly the single line of standard output produced by the code below. Do not include an explanation.
class A:
    def __init__(self):
        self.s = "A"
class B(A):
    def __init__(self):
        super().__init__()
        self.s += "B"
class C(A):
    def __init__(self):
        super().__init__()
        self.s += "C"
class D(B, C):
    def __init__(self):
        super().__init__()
        self.s += "D"
print(D().s)
3. In Python 3, write exactly the single line of standard output produced by the code below. Do not include an explanation.
x = 1
class T:
    x = 2
    y = [x]
    z = [x for _ in range(1)]
print(T.y, T.z)
